3.2 与大语言模型交互

3.2.1 提示工程（Prompt Engineering）

（1）模型采样参数

控制模型输出的随机性、确定性、多样性，直接影响生成效果，核心参数如下：

参数 作用 取值影响 经典取值 极端情况
Temperature（温度） 控制输出随机性，调整概率分布陡峭程度 - 越大：输出越发散、有创意
- 越小：输出越保守、精准		 0.3-1.0
（创意：0.7-1.0；严谨：0.1-0.3）		 - $T \to 0$：输出完全确定（选概率最高Token）
- $T=1$：标准概率分布
Top-k 固定保留前 $k$ 个高概率Token，限制候选范围 - 越小：输出越保守
- 越大：输出越多样		 20 / 40 / 50 - $k=1$：贪心采样（仅选最高概率）
- $k \to \infty$：无截断，全候选
Top-p（核采样） 动态筛选累积概率≥$p$的最小Token集合 同 Top-k，自适应概率分布 0.7 / 0.8 / 0.9 - $p=1$：无截断
- $p \to 0$：等价贪心采样

参数优先级

Temperature → Top-k → Top-p

  • 先通过 Temperature 调整整体概率分布
  • 再用 Top-k/Top-p 筛选候选Token
  • 通常 Top-k 与 Top-p 二选一，同时设置时取两者交集

（2）Zero-shot 学习（零样本学习）

  • 核心定义：模型利用预训练阶段学到的通用知识，无需额外样本（数据+标签），直接完成陌生新任务。
  • “Zero”含义：训练时未见过该类任务样本，测试时可直接推理。

（3）Few-shot 学习（少样本学习）

  • 核心定义：在提示中提供少量（1~5个）输入-输出示例，引导模型学习任务格式与规则，提升回答的对齐精度。

（4）指令调优（Instruction Tuning）的影响

  • 早期模型：仅能“文本续写”，无法理解并执行人类指令。
  • 优化后：用大量指令-回答数据微调，模型可直接理解自然语言指令（如“翻译句子”“总结文本”），无需额外示例。

（5）基础提示技巧

  • 角色扮演（Role-playing）：给模型设定专属身份（如“资深Python专家”“中学老师”），规范输出风格、语气与知识范围。
  • 上下文示例（In-context Example）：在提示中给出清晰输入-输出样例，引导模型遵循指定格式/风格处理任务。

（6）思维链（CoT, Chain-of-Thought）

  • 核心作用：解决复杂推理（计算、逻辑题）易出错问题，提升推理准确率。
  • 实现方式：提示中加入引导语（如“请逐步思考”“Let's think step by step”），强制模型分步推理、展示过程。
  • 优势：推理过程透明，便于检查错误、纠正逻辑。

3.2.2 文本分词（Tokenization）

（1）分词的核心目的

将原始文本转换为模型可处理的离散基本单元（Token），同时解决三大问题：

  • 避免词表过大，降低管理难度
  • 防止未登录词（OOV）无法识别
  • 保留语义关联，避免语义丢失

（2）主流分词算法：子词分词（Subword Tokenization）

  • 核心逻辑：兼顾词表大小与语义表达
    • 常见词：完整保留（如 agent）
    • 生僻/长词：拆分为有意义子词（如 Tokenization → Token + ization）
  • 优势：控制词表规模，支持新词生成，保留词根语义关联。

（3）经典子词算法对比

① 字节对编码（BPE）

  • 代表模型：GPT 系列
  • 核心逻辑：贪心合并高频相邻字符/子词对
    1. 初始化：词表为所有基础字符
    2. 迭代：统计高频相邻词元对，合并为新词元
    3. 终止：词表大小达到预设阈值
  • 示例：新词 bug → 拆分 ['b', 'ug']

② WordPiece

  • 代表模型：BERT
  • 核心差异：合并标准不是“频率最高”，而是最大化语料通顺度（概率）。

③ SentencePiece

  • 代表模型：Llama 系列
  • 核心特点：将空格视为普通字符（用 _ 表示），分词/解码可逆、多语言兼容。

（4）分词对开发者的关键意义

  • 上下文窗口限制：窗口大小（8K/128K）按 Token 数量计算，不同语言/分词器下，相同文本 Token 数差异大。
  • API 成本控制：主流模型 API 按 Token 计费，理解分词规则可精准预估、降低成本。
  • 避免模型异常：空格、大小写差异会改变分词结果，导致模型理解错误；设计提示词时需规避此类陷阱。
